# リポジトリ作業の運用

- コミットメッセージの件名・本文、PR のタイトル・本文、レビューコメントなど GitHub 上に書く説明は日本語で書く。コード識別子、コマンド、固有名詞は必要に応じて原表記を保つ。
- 必要な作業が完了し検証できたら、コミットはユーザーの追加確認を待たずに行ってよい。タスクに不要なコミットや PR は作らない。
- リモートへのプッシュは、その対象の変更についてユーザーが明示的に依頼した場合だけ行う。過去の別タスクでのプッシュ依頼や、コミット・PR 作成の許可をプッシュ許可として扱わない。PR 作成にプッシュが必要で明示されていない場合は、変更とコミットを準備した後にプッシュの許可を求める。
- 機能を変更したら、対応するユーザー向け・開発者向け文書を同じ作業で更新する。操作方法、設定、既定値、制約、設計のうち変更に関係する箇所を選ぶ。
- 作業完了前に、変更箇所に関連する古い説明、不要になったコード・ファイル、旧名称、テストや設定の更新漏れを検索して確認する。無関係な領域まで掃除しない。
- 変更に応じたテストと差分確認を行い、残った制約や未更新箇所があれば報告する。
