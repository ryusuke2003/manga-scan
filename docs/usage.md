# Web UI・撮影ガイド

Manga Scan Localで撮影からレビュー、PDF / CBZ出力まで進める手順です。

> [!IMPORTANT]
> 各見開きで **0.5〜1秒程度静止する**ことが、安定した自動抽出で最も重要です。

## Web UIの使い方

### 1. 入力を選ぶ

動画の場合は `.mov` / `.mp4` のローカルファイルを選択します。
ブラウザへ巨大動画そのものをアップロードするのではなく、ローカルパスだけを渡します。

動画ではなくページ写真が揃っている場合は、新規スキャン画面で **静止画フォルダ** を選べます。
PNG / JPEG / WebPをファイル名の自然順（1, 2, 10…）で一括読み込みし、
EXIFの向きを反映してそのままレビューへ進みます。

### 2. 読み方・出力・補正を選ぶ

- 出力形式は「見開きのまま」が標準
- 「左右のページに分割」も選択可能
- 分割時の日本漫画の読む順番は通常「右 → 左」
- PNGは画質優先、JPEGは容量優先
- 補正は「原画優先 / 標準補正 / スキャン風」のプリセットから選択
- 画像の向きはデフォルトで自動判定
- 左右ページを別候補から選ぶ `per_page` モードも利用可能
- 「別フレームから指を補修」をONにすると、同じ見開きの別候補に実在する画素だけで補修
- 詳細設定では台形、外周、分割位置、湾曲、照明ムラ、白背景などを個別調整

補正内容の詳細は [設定・チューニングガイド](configuration.md) を参照してください。

### 3. 表紙を追加する（任意）

表紙が映っている時刻を `±0.1秒 / ±1秒` で選びます。
表紙の外周を自動検出し、1ページとして保存します。
検出できない場合だけ4点を指定します。
抽出後に机が入る・表紙が見切れる場合は、レビュー画面の「表紙の外周を修正」で四隅を指定し直せます。

表紙が不要ならスキップできます。

### 4. 見開きの基準フレームを選ぶ

最初に本を開いて左右2ページが見えている時刻を選びます。

自動判定した向きでプレビューされます。
動画の回転メタデータを優先し、無い場合は低解像度の複数フレームから
0 / 90 / 180 / 270°を推定します。

ページ形状だけで上下を判別しにくい場合やconfidenceが低い場合は確認を求めます。
正しければそのまま確定し、違う場合は手動で向きを変更できます。

この時刻より前は、自動の見開き検出から除外されます。

### 5. 見開き外周を確認

基準フレーム全体から左右ページを自動検出し、
両ページの外側4点から見開き外周を作ります。

検出できた場合は四隅が最初から表示されるので、
正しければクリックせず「この範囲で抽出開始」を押します。

confidence不足や不正な形状で自動検出できない場合だけ、
`左上 → 右上 → 右下 → 左下` の順に4点指定します。

表紙用ROIとは別で、実際の見開きサイズに合わせます。

### 6. 抽出を開始

基準時刻以降から動きが小さい区間を探し、候補フレームを評価します。

### 7. 要確認ページと動画タイムラインをチェック

レビュー画面では主に次を確認します。

- 手の重なり
- ブレ
- 反射
- 重複候補
- ページ外周
- 欠落候補
- 見開き間の時間関係

まず本文や絵が欠けず、指・ブレ・反射で読めない部分がないかを確認します。
読める候補の中では、机の写り込みやページの湾曲も確認します。
手の少ない画像が後から見つかった重複見開きでは、ピントや外周などの確認を通れば採用ページを自動で切り替えます。

検出済み見開きは動画全体のタイムラインでも確認できます。

新規スキャンでは、ページめくりイベント同士の間に安定区間が無い箇所を
「欠落候補」として表示します。
候補時刻には、その区間で最もmotionが小さいフレームを使います。

### 8. 必要なら修正

レビュー画面から次を変更できます。

- 見開きごとの出力形式切り替え（見開き / 左右分割）
- 候補フレーム切替
- 左右片側だけの候補差し替え
- 元画像 / 補正後の100%・200%・400%ズーム確認
- 問題ページだけ `±0.5 / ±1 / ±2秒` を30/60fpsで再探索
- 採用候補の外周確認・手動調整
- 表紙の外周修正
- ページ除外 / 復元
- ドラッグまたは ← / → によるページ順変更
- 左右交換
- 分割位置修正
- Undo / Redo（最大30履歴）

通常候補がすべてブレ・指・反射・高motionで要確認の場合は、
その見開き区間だけ自動で高fps再探索し、候補を追加・再選択します。

ページ抜けv2の欠落候補も高fpsで再確認し、
短くても連続した低motion区間が見つかった場合だけ自動復旧します。

各見開きの複数候補は採用候補へ位置合わせしてからページ輪郭をconsensusし、
指・影・一時的な境界誤検出を外れ値として除外します。

撮影中に本が少し動いた場合は、
直前の採用見開きの本ROI内部だけをoptical flowで追跡して次の見開きへ反映します。
大きすぎる移動や低confidence時はtrusted ROIへfallbackします。

### 9. 見落とした見開きを追加

動画の秒数を指定して見開きを追加できます。
タイムラインの欠落候補は推定なので、元動画を確認してから追加してください。

Review画面からPNG / JPEG / WebP画像を新規ページとして追加したり、
失敗した1ページだけ外部画像で差し替えたりすることもできます。

### 10. ページ数と改善候補を確認

任意で期待ページ数を設定すると、
見開きを2ページとして数えた物理ページ数と最終結果を照合します。

QAに引っかかったページでは、
既存候補のうち新しい既知リスクを増やさず改善が見込めるものだけを
「安全な改善候補」として表示します。

### 11. PDF / CBZを出力

編集後は「PDF / CBZを出力」で変更を反映します。

出力ファイルの構成や保存方式は [CLI・出力ガイド](cli.md) を参照してください。

## プロジェクト操作

### 除外と復元

除外は非破壊です。
自動で重複除外されたページも「除外ページも表示」から復元できます。

### プロジェクト削除

左のプロジェクト一覧から不要なプロジェクトを削除できます。

削除すると、そのプロジェクト内の生成ページ・候補画像・PDFも消え、元に戻せません。
プロジェクト外の元動画ファイルは削除しませんが、
`--copy-source` でプロジェクト内に作った動画コピーは一緒に削除されます。

### 処理の中断・再開

ブラウザを閉じても、サーバープロセスが動いている間は処理を続けます。

処理中はレビュー画面の「処理を停止」から安全な区切りで中断できます。
動き解析が完了していれば、完了済み見開きを保持したまま「続きから再開」できます。

動き解析中に停止した場合は、再開時に動き解析だけ最初からやり直します。
ターミナルを終了するとプロセス自体が停止します。

Macのスリープを避ける場合は次のように起動できます。

```bash
caffeinate -i manga-scan ui --config config.toml --projects projects
```

## 撮影のコツ

- スマホを真上の固定スタンドに置く
- 表紙を撮ったあと、本を開いた最初の見開きでも少し静止する
- 見開きを画面いっぱいに入れる
- 本とスマホを途中でなるべく動かさない
- 反射や強い影を避け、可能ならAF/AEを固定する
- まずは **4K・30/60fps・SDR** を推奨
- 1枚めくるごとに **0.5〜1秒程度静止**する
- 静止中は可能なら指をページから離す
- 指補修を使う場合も、同じ場所が少なくとも1候補では見えるようにする
- 最後の見開きも少し静止してから録画を止める

120/240fps入力も扱えますが、解析フレーム数は設定したsample fpsまで落とします。
iPhoneスローモーションの実撮影fpsを推測して時間を変換することはしません。
