# 設定・チューニングガイド

Web UIの補正設定や `config.toml` の主要項目、
うまく抽出できないときの調整方法をまとめています。

設定値の完全な一覧と現在のデフォルト値は
[config.example.toml](../config.example.toml) を正としてください。

プロジェクト作成時の設定は `config.resolved.json` にスナップショット保存されます。
自動解析に関わる値を変更した場合は、新しいプロジェクトで試すのが確実です。

## 出力形式

### 見開き出力

新規プロジェクトのデフォルトは `output_layout="spread"` です。

採用候補ごとに左右ページの四隅を自動検出し、
左ページの左上・左下と右ページの右上・右下から見開き全体の外周を作ります。
中央の綴じ目は切らずに1枚で保存します。

左右どちらかの検出が不確かな場合は基準範囲へ戻し、要確認として表示します。
指補修・照明補正・白背景・グレースケールは引き続き適用されます。
表紙は1ページとして保存します。

### 左右分割

`output_layout="split"` またはWeb UIの「左右のページに分割」で左右分割できます。

既存プロジェクトは現在の出力形式を維持し、
レビュー画面から見開きごとに切り替えられます。
切り替え前の除外状態と左右の並び順は、元の形式へ戻したときに復元します。

余分な背景や切りすぎた端は、
採用中の候補の「外周を確認・調整」で修正できます。

## 補正プリセット

新規スキャン画面では、`config.toml` を直接編集しなくても主要な補正を設定できます。
起動時の `config.toml` にカスタム値がある場合は、その値をUIの初期値として表示します。

- **原画優先**: 見開き全体補正を使い、自動湾曲・照明・白背景を抑える
- **標準補正 / おすすめ**: 左右別台形、自動外周微調整、自動split、自動湾曲、照明ムラ補正を有効化。白背景正規化はOFF
- **スキャン風**: 標準補正に白背景正規化も加える
- **カスタム**: 詳細設定を変更した状態

詳細設定では主に次を変更できます。

- `auto_rotation` / `rotation`
- `refine_quad`
- `perspective_mode`
- `page_contour_min_confidence`
- `split_mode`
- `dewarp_mode`
- `illumination_correction`
- `white_normalization`

UIから選んだ値も `config.resolved.json` へ保存されます。

## 指補修

指補修はデフォルトONです。

`finger_repair=true` の場合、
MediaPipeで保存済みの手マスクをページ座標へ写し、
同じ見開き区間の別候補をOpenCVで位置合わせします。

採用ページで指と判定された画素のうち、
donor側で手に隠れていない場所だけを実画素で置き換えます。
生成AIやinpaintingモデルは使いません。

位置合わせが不確実なdonorは使わず、
復元率が `finger_repair_min_coverage`（既定90%）未満なら
残りを元画素のまま `finger_repair_incomplete` として要確認にします。

白黒ページでは、ページ端につながる小さな肌色領域も補助マスクに追加します。
手全体が映っていない指先の見逃しを減らすための処理です。

肌色の印刷や照明による誤検出はあり得ます。
「指を未検出」は、指がないことの保証ではありません。
全候補で隠れている部分は補修できません。

## 見開き外の背景

見開き出力では `page_background_fill="paper"` が既定です。

左右ページの輪郭を十分なconfidenceで自動検出できた場合だけ、
両ページと中央のノドを保護maskにし、その外側に残った机・背景を紙色で隠します。

- `paper`: ページ外を推定した紙色で隠す
- `preserve`: 背景を変更しない
- `white`: ページ外を白で隠す

輪郭検出がfallbackした場合や手動外周だけの場合は、
安全のため背景を変更しません。

## 候補選択

デフォルトは `candidate_selection_mode="spread"` です。

`"per_page"` では同じ候補群を左右ページごとに再採点し、
鮮鋭度・手の重なり・露出などから別々の候補IDを選びます。
レビュー画面から左右片側だけ差し替えることもできます。

通常候補がすべてブレ・指・反射・高motionで要確認なら、
`auto_high_fps_fallback` により、その見開き区間だけ高fpsで再探索します。
欠落ページの再探索では近い時間窓をまとめてdecodeします。
短い復元区間が既存ページと明確に同じ画像なら、その候補を既存ページへ追加してから採点します。

## 台形補正とページ輪郭

分割出力時の台形補正は
`perspective_mode="spread"` がデフォルトです。

この設定は `output_layout` とは別です。

`"spread"` は見開き全体を補正してから分割します。
`"per_page"` は元フレーム上で左右ページの外周を検出し、
左右を別々の射影変換で補正します。

両ページの輪郭confidenceが閾値に届かない見開きは
`page_contour_low_confidence` として要確認にし、
「見開き全体を補正 → 左右分割」へfallbackします。

検出quadとconfidenceはmanifestに残り、
`debug/page_contours/` に確認画像を保存します。

## ROI追従と背景混入

白黒の紙面と色のある机・表紙を区別できる場合は、
基準ROIの外側も画像の長辺の5%まで探索し、小さな本の移動に追従します。

探索枠そのものを紙の境界と誤認した結果や、大きすぎる変化は採用しません。
ページが元フレームの端まで達している場合は、
「元動画の画面端に接触・見切れを確認」と表示します。

候補画像では紙面と机の前景分離を使い、
ROIが大きすぎる場合は机を削り、小さすぎる場合は紙面側へ広げます。
手動で修正したROIは優先されます。

ページの下に表紙が見えるケースでは内側の長い境界も調べますが、
印刷された帯を誤って切らないよう、判断がつかない場合は外側の枠を維持してレビューを促します。

## 自動湾曲補正

`dewarp_mode="auto"` では、
左右分割後の各ページについて背表紙側の横方向圧縮を画像内容から推定します。

```toml
dewarp_mode = "auto"
dewarp_max_strength = 0.25
dewarp_min_confidence = 0.6
```

ページ上端から下端まで複数の高さ帯で縦エッジ間隔を測り、
背側の横方向圧縮を高さごとに推定します。

補正量を1ページ全体で固定せず、
上・中央・下で異なる強さの2D remapを使います。

十分に測定できない場合は補正せず、ページを要確認にします。
完全な3D復元や文字認識は行いません。

レビュー画面ではページごとの最大補正量・高さ方向差・信頼度を確認できます。
自動モードでは `debug/dewarp/` に補正前PNGと確認用グリッド画像を保存します。

固定補正も利用できます。

```toml
dewarp_mode = "manual"
dewarp_strength = 0.15
```

`dewarp_mode="off"` なら湾曲補正を無効化します。
表紙は自動モードの対象外です。

見開き全体の `rotation` は左右分割より前に適用されます。
ページ分割後の補正順は
**湾曲補正 → 照明ムラ補正 → 白背景正規化 → grayscale / contrast** です。

## 照明ムラと白背景

照明ムラ補正はデフォルトONです。
ページ単位の低周波な明るさだけを均し、二値化や背景除去は行いません。

黒ベタや網点への影響が気になる場合は
`illumination_strength` を下げるかOFFにしてください。

白背景正規化もデフォルトONです。
暗部はほぼ触らず、明るい紙面候補だけを白へ寄せます。
薄いトーンを残したい場合は `white_strength` を下げてください。

## チューニング早見表

| 症状 | 主な調整 |
|---|---|
| 候補がない / 少ない | 静止時間を伸ばす。`stable_frames` を5→3、sample fpsを10→15 |
| 微振動で静止判定されない | `motion_threshold` を少し上げる |
| 別ページが1区間になる | `turn_threshold` を下げる |
| 同じページが繰り返される | `turn_threshold` を上げる / 重複SSIMを少し下げる |
| 指の少ない候補を拾わない | `candidates_per_spread` を増やし、手の検出が有効か確認する。ブレや欠けがある候補は手の面積が小さくても採用しない |
| 左右でベストな瞬間が違う | `candidate_selection_mode="per_page"` |
| 左右ページで台形の向きが違う | `perspective_mode="per_page"` |
| 自動ページ輪郭が不安定 | `page_contour_min_confidence` を上げる |
| 背の位置がずれる | UIで分割位置を修正。必要なら `split_mode="auto"` |
| 横向き撮影で上下に割れそう | `auto_rotation=true` を使い、必要時だけ手動回転 |
| ページの端/中央が緩く暗い | `illumination_correction=true`。強すぎる場合は強度を下げる |
| 紙が黄ばみ/グレーに見える | `white_normalization=true` |
| 黒ベタや網点が変わる | 照明・白背景・dewarpを弱める/無効化し、PNGを使う |
| PDFが大きい | `image_format="jpeg"`、`jpeg_quality=90` 前後 |
| decodeが遅い | VideoToolboxをデフォルト利用。初期化失敗時はMac上でCPUへfallback |

`turn_threshold >= motion_threshold` は維持してください。

## 性能設定

処理時間の内訳は `debug/performance.json` に保存され、
`debug/process.log` にも `PERF` 行として記録されます。

通常候補とhigh-fps再スキャン候補は、
複数timestampを1回のFFmpegプロセスでまとめてdecodeします。

候補解析と指補修のdonor alignmentは
`processing_workers`（デフォルト3、最大4）で並列化し、
分割出力の左右ページは最大2並列でrenderします。

対応MacではVideoToolboxをデフォルト利用し、初期化失敗時はCPUへ自動fallbackします。
トラブルシュート目的でCPU decodeを明示したい場合だけ `hwaccel = "none"` を指定してください。
